# 部署与使用

## 安装进 dsh

```sh
# 方式一：本地目录（开发/自用）
dsh plugin --profile web add /home/loker/Desktop/测试项目/商城插件

# 方式二：GitHub 仓库（发布后）
dsh plugin --profile web add github:loker66fan/dsh-market-github
```

安装后**重启 dsh web** 生效。之后：

- **启动页**：首次运行（无会话）引导流程会出现「插件商城」步骤，点一次「完成 / 跳过」后永久不再弹出（localStorage 持久化）。
- **随时访问**：设置 → 插件 → 「插件市场」（搜索/安装）与「已安装」（启停/更新/卸载）两个标签页。
- **agent 工具**：模型可自行调用 `market_search` / `market_install` / `market_installed` / `market_update`。

## 常用配置

| 配置 | 位置 | 说明 |
|---|---|---|
| 每页条数 | `cordis.patch.yml` 的 `config.perPage`（默认 50，1–100） | 市场列表分页大小 |
| GitHub 搜索配额 | 环境变量 `GITHUB_TOKEN` | 未鉴权 10 次/分钟；带 token 更高 |
| 本地代理 | 无需配置 | 自动探测（env 变量 → 系统代理 → 常见本地端口 7890/7897/1080…），见提交 `7901d5f` |
| dsh CLI 路径 | 市场面板顶部输入框 | 自动探测失败时手动填（记在 localStorage `mktsBin`） |

## 源码开发

```sh
cd /home/loker/Desktop/测试项目/商城插件
npm install        # 依赖（devDeps 含 dsh-client-* 发布包，用于类型）
npm run build      # tsc host → lib/host.js；tsdown → lib/client.js
npm test           # node --test（host 路由/管线 + 工具函数）
```

- Host 半：`src/host.ts`（HTTP 路由 `/api/dsh-market` + 4 个模型工具 + 安装管线）。
- Client 半：`src/client/index.ts`（市场/已安装/onboarding 三个注册面 + op-bus 进度总线）、`src/client/op-bus.ts`、`src/client/market-css.ts`。
- 测试：`tests/host.test.mjs`（离线安全：fake bin + 临时 DSH_HOME）。

## 已知坑（踩过）

1. **纯客户端插件不能进 `dsh.profile.bundles`**：只声明 `dsh.client` 的包（如 `@deepseek-ai/dsh-client-ui-aqua`）若出现在 bundles 里，dsh boot 会抛 `declares no dsh.bundle`。正确形态：留在 `dependencies`，由市场的 `ensureClientRow` 在 profile 的 `cordis.patch.yml` 写合成行。手动装这类包时不要手改 bundles。
2. **GitHub 直连不稳**：安装走 codeload tarball（`codeloadSpec`），manifest 读取依次试 GitHub contents API → raw 镜像（jsdelivr/ghproxy）。
3. **pnpm ≥10 构建脚本拦截**：验证通过的 git 包会在 profile 的 `pnpm-workspace.yaml` 精确放行 `allowBuilds` 键（`ensureAllowBuilds`），跳过安全检查则不放行。
4. **模型工具装包较慢**：`market_install` 同步跑完 pnpm + 试装验证才返回（最长约 4 分钟），UI 安装走后台 op 不阻塞。

## 相关：modlens 视觉插件（同机部署，供参考）

`@liustack/modlens`（vision 读图）配置要点，与本市场无关但常见同装：

- 安装：`dsh plugin --profile web add @liustack/modlens@3.16.6`（重启用 `(modlens vision)` 模型条目）。
- 引擎：`~/.modlens/config.json`（0600）——`provider: gemini-api` + `gemini-api.apiKey`。
- **网络是重灾区**：直连 Google 超时是「无法使用」的最常见原因。本机代理 `127.0.0.1:7897`；modlens 3.16.6 已二次开发为**默认自动探测本机代理**（TCP 扫描常见端口 + 真实转发验证，`MODLENS_NO_AUTO_PROXY=1` 可关），无代理机器零开销。改动源码在 `/tmp/modlens-src/src/net/proxy.ts`（若仍存在）。
